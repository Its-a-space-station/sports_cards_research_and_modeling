## Panel

`data/processed/panel_class.parquet`: **93,969 rows** (card × entry-month;
unique per card-grade-month, entries ≥ 2021-04 via the reviewed multiyear
floor), **1,639 cards, 1,639 players**. Built 2026-09-19 in ~8 min. Note the
entry-month column is named `month` here vs `entry_month` in
panel_multiyear.

Feature coverage (share of 93,969 rows):

| feature | non-NA rows | share | why |
|---|---|---|---|
| `draft_rank` | 39,120 | **41.6 %** | structural: visible to entries after July 1 of the player's class/draft year; 2015/2016 rank=NA at source; international signees have no draft board |
| `surprise_ops` | 7,361 | **7.8 %** | structural (below) |
| `surprise_era` | 3,689 | **3.9 %** | structural (below) |
| `prospect_rank` / `rank_change` / `fg_draft_fv` | 0 | **0.0 %** | Pipeline leg blocked; FG leg replaced by statsapi draft prospects |

Surprise coverage is low **by construction**: a surprise value needs (a) a
Marcel prior, which requires ≥ 1 completed prior MLB season plus a non-empty
league regression target truncated at the entry month, and (b) in-season MLB
pace strictly before the entry month. Pre-debut and rookie-entry rows —
exactly the rows where a surprise term would be most interesting — carry NaN.
**Treat surprise as a mostly post-debut feature**, not a pre-debut one.

Era split: `price_visible_breakout` (first pro season ≥ 2020) is True on
**69,676 rows = 74.1 %** — the early-prediction core per spec; classes
2015–2019 contribute late-window rows only (SCP's price archive floor is
2021-03). Players with zero collected logs default to True (first_pro =
9999), a known deferred minor.

Liquidity (`data/processed/class_liquidity.csv`, 4,245 card×grade rows over
1,639 cards): median 2 sales per card×grade, median 0.0069 sales/week
(≈ 1 sale per ~2.8 years), max 31 sales; median 33 monthly chart points.
These cards are thin by design — raw base 1st Bowmans of a mostly-bust
cross-section — which is why the panel carries the full entry-month
outcome grid rather than per-sale granularity.

## Caveats

- **Draft-checklist completeness is CC-audited for 2019 only** (ok=True,
  completeness 1.0). Completeness of the other 10 draft years is
  extrapolated, not audited; the 2015 chrome audit covers that set only.
- **Residual unmapped players (99)**: 66 `no_exact_match` (absent from
  people/search AND all 91 sport×season directory cells — genuinely outside
  MLB's register: unsigned, register purges, or name forms beyond the
  suffix/nickname rules), 1 `ambiguous:directory duplicate`, 32
  `ambiguous:timing` (common-name collisions; notable names table above).
  These players keep checklist/auto rows but have no mlb_id → no stats,
  events, or expectations features.
- **`key:*` filter convention**: 15,843 uncalibrated `key:*` chart rows EXIST
  in `class_chart_monthly.parquet`; every consumer must filter
  `grade.str.startswith("key:")` (`build_class_panel.main()` does). 0 cards
  are `key:*`-only.
- **Surprise-coverage structure**: requires ≥ 1 prior MLB season (Marcel) +
  in-season pace strictly before entry → mostly a post-debut feature; the
  7.8 % / 3.9 % coverage is structural, not a bug.
- **`surprise_era` sign asymmetry**: `build_class_panel.py` computes surprise =
  pace − marcel identically for both groups, so a POSITIVE `surprise_era` is a
  higher-than-projected ERA, i.e. WORSE — opposite in meaning to a positive
  `surprise_ops`; T2-model must flip its sign (or interpret it inverted) before
  treating it as a breakout signal.
- **Pipeline-missing implication for T2-model**: the prospect-expectations
  term is currently limited to `draft_rank`, which exists only for
  US/CA/PR-draft eligible players (no international signees) and only for
  2017–2025 classes (2015/2016 rank=NA at source). `prospect_rank`,
  `rank_change`, and `fg_draft_fv` are all-NA until the Pipeline leg lands —
  models must not treat their absence as "unranked".
- **Debut details caveat**: all 925 debut rows say "first game in dataset" —
  the first game in the collected window (MLB logs from 2015, minors from
  2014), not necessarily the true MLB debut for careers predating the window.
- **`resolution_source` provenance**: empty for the 2,326 rows resolved
  before round 4 (provenance was not yet recorded); populated only for
  round-4+ resolutions (search 11, directory 2, timing 41). Full provenance
  requires a from-scratch re-resolve.
- Smaller notes: 19 `mlb_draft` rows have `player_name` NaN (mlb_id present);
  era flag defaults True for log-less players; 2019 draft expectations volume
  is a source outlier (5,132 rows); `class_price_failures.csv` mixes
  permanent `no_scp_url` skips with retryable `parse:*` failures (filter on
  reason); Marcel is an in-house 5/4/3 + 1,200-PA regression baseline, not
  Steamer; panel uses `month` where panel_multiyear uses `entry_month`.

## Reproduce

Exact commands, in order (worktree root; live runs were controller background
jobs — never subagent-run):

```bash
# 1. Checklists (Playwright; brand discovery -> 22 auto sets + 19 base sets
#    + CC cross-audits 2015 chrome & 2019 draft)
PLAYWRIGHT_BROWSERS_PATH=.pw-browsers .venv/bin/python scripts/build_class_checklists.py

# 2. Universe resolution (statsapi; incremental CSV, crash-safe resume).
#    The 5-round remediation arc is plan amendments af6d2d2..1d1142d; final code
#    resolves in one pass. Controller-run post-passes:
.venv/bin/python scripts/resolve_class_universe.py
#    - audit_multi_validated(mapped players) -> class_multivalidated_audit.csv (73 rows)
#    - disambiguate_by_career_timing(class_year, validated_ids) per audit row
#      -> class_timing_disambiguation.csv (41 ok:timing / 32 ambiguous:timing)

# 3. Stats: partition universe into 4 shard CSVs on mlb_id %% 4
#    (data/processed/stats_shard_{0..3}.csv), then 4 parallel collectors:
.venv/bin/python scripts/collect_class_stats.py --cards data/processed/stats_shard_0.csv --out data/processed/game_logs_class_shard_0.parquet
.venv/bin/python scripts/collect_class_stats.py --cards data/processed/stats_shard_1.csv --out data/processed/game_logs_class_shard_1.parquet

.venv/bin/python - <<'EOF'   # merge shards
import pandas as pd
pd.concat([pd.read_parquet(f"data/processed/game_logs_class_shard_{i}.parquet")
           for i in range(4)]).to_parquet("data/processed/game_logs_class.parquet", index=False)
EOF

# 4. Prices (resumable part files; rerun the same command to retry failures)
.venv/bin/python scripts/collect_class_prices.py
.venv/bin/python scripts/collect_class_prices.py --merge-only   # re-merge parts only

# 5. Events (requires game_logs_class.parquet)
.venv/bin/python scripts/collect_class_events.py

.venv/bin/python scripts/collect_draft_prospects.py
```
